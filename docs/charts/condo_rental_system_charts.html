Systems Analysis and Design, semester project

Condo & Apartment Rental System

Three charts drawn from the project plan: how the system is built, how a rental moves from search to confirmed booking, and how the ten proposed tables relate.

1. Architecture2. Process flow3. Database

1. System architecture

A standard three-tier web application. The browser talks to one backend over HTTP. The backend is split into the seven process modules from Diagram 0, all sharing one relational database plus a file store for room photos. Bookings are confirmed directly by the owner, so there is no deposit or payment step in the system.

2. Process flow: search to review

Swimlane view of the core user journey. Rows are the actors, columns are time. The teal path is the happy path from the demo scenario; dashed amber edges loop back, dashed red edges end the request.

2.1 Booking status machine

States of one Bookings row. The owner drives every transition; the system only updates the room status alongside it.

3. Database design (ERD)

The ten tables from section 7.1, one field per line. Properties sits at the top and fans down to the tables that reference it; Users sits at the bottom and fans up to the tables that reference it. No two lines cross.
